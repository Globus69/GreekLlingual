## 📊 Database Changes

### New Tables
```
user_vocabulary_progress
├── id (UUID, PK)
├── user_id (UUID, FK → users)
├── vocabulary_id (UUID, FK → multilingual_vocabulary)
├── fsrs_difficulty (REAL)
├── fsrs_stability (REAL)
├── fsrs_due (TIMESTAMPTZ)
├── fsrs_reps (INT)
├── fsrs_lapses (INT)
├── fsrs_state (TEXT: 'new' | 'learning' | 'review' | 'relearning')
├── fsrs_last_review (TIMESTAMPTZ)
├── created_at (TIMESTAMPTZ)
└── updated_at (TIMESTAMPTZ)

Indexes:
- idx_user_vocab_progress_user_id
- idx_user_vocab_progress_vocabulary_id
- idx_user_vocab_progress_due
- idx_user_vocab_progress_state
- idx_user_vocab_progress_user_due
```

### New RPC Functions
```sql
1. get_due_cards_fsrs(p_user_id, p_level, p_limit)
   → Returns vocabulary cards due for review (with FSRS data)

2. init_user_vocabulary_progress(p_user_id, p_level)
   → Initializes progress records for user

3. update_card_fsrs(...)
   → Updates FSRS parameters after review

4. get_due_vocabulary_cards(p_user_id, p_limit)
   → Alias for get_due_cards_fsrs

5. update_vocabulary_progress(...)
   → Alias for update_card_fsrs
```

## 🔧 Technical Notes

### FSRS-6 Implementation
- FSRS (Free Spaced Repetition Scheduler) in `user_vocabulary_progress` implementiert
- Difficulty und Stability werden pro User/Vocabulary-Item getrackt
- Due-Dates werden automatisch berechnet
- State-Machine: new → learning → review → relearning

### RLS (Row-Level Security)
- Cloze Text: Server-side API mit service_role key (bypasses RLS)
- User Vocabulary Progress: RLS Policies aktiv (users can only access own progress)

### Database Schema
- `multilingual_vocabulary`: Core vocabulary data (no FSRS fields)
- `user_vocabulary_progress`: User-specific FSRS tracking
- `daily_phrases`: Daily phrases (currently empty)
- `cloze_texts`: Fill-in-the-blank exercises
