### **3.2 Matching Game testen**

**Voraussetzung:** Mindestens 1 Item mit `threshold=0` muss vorhanden sein

**Test-Ablauf:**
1. Finde Item mit "Matching" Button (unlocked)
2. Klicke "🎮 Matching" Button
3. **Erwartet:** Dialog öffnet mit 6 Paaren (Greek + English)

**Spiele komplett durch:**
- [ ] Karten klicken → Paare matchen
- [ ] Shake-Animation bei Fehler?
- [ ] Matched pairs disabled/verschwinden?
- [ ] Score wird live aktualisiert?
- [ ] Timer läuft (falls aktiviert)?
- [ ] Nach allen Matches → Result Summary erscheint?

**Result Summary prüfen:**
- [ ] Score korrekt (0-100)?
- [ ] Zeit angezeigt (MM:SS)?
- [ ] FSRS Rating chip (1-4) mit Farbe + Emoji?
- [ ] Mistakes count korrekt?
- [ ] "Try Again" Button funktioniert?
- [ ] "Close" Button schließt Dialog?

### **3.5 DB-Verifizierung (KRITISCH!)**

**In Supabase SQL Editor ausführen:**

```sql
-- Check practice_attempts
SELECT
  id,
  user_id,
  item_id,
  mode_type,
  score,
  time_taken,
  fsrs_rating,
  created_at
FROM practice_attempts
ORDER BY created_at DESC
LIMIT 5;
```

**Erwartete Ergebnisse:**
- ✅ Neue Einträge für jedes gespielte Game
- ✅ `mode_type` korrekt: 'matching', 'multiple_choice', 'write_input'
- ✅ `score` zwischen 0-100
- ✅ `time_taken` in Sekunden
- ✅ `fsrs_rating` zwischen 1-4
- ✅ `user_id` und `item_id` korrekt

**Falls KEINE Einträge:**
- ⚠️ BLOCKER! RPC `record_practice_attempt` funktioniert nicht!
- Notiere in FINDINGS.md

### **3.6 FSRS Integration prüfen**

**In Supabase SQL Editor:**

```sql
-- Check if FSRS updated
SELECT
  item_id,
  student_id,
  fsrs_reps,
  fsrs_stability,
  fsrs_difficulty,
  fsrs_due,
  updated_at
FROM student_progress
WHERE item_id = '<item_id_from_practice>'
ORDER BY updated_at DESC
LIMIT 1;
```

**Prüfe:**
- ✅ `fsrs_reps` inkrementiert?
- ✅ `fsrs_stability` aktualisiert?
